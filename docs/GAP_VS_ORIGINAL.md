# 与原版的差距清单

> 对照基准：《Balatro》1.0（PC / 主机版），不作为商业对标，仅作设计参照。
> 本文每一条都标注了判定依据（文件:行号），凡是写"缺"的，都在当前代码里
> 检索过关键词并确认无实现。

---

## 0. 先说结论

内容量已经**逐项对齐**，这一层没有缺口：

| 项 | 原版 | 本作 | 判定 |
|---|---|---|---|
| 小丑 | 150 | 150（`Joker.kt` `val ALL`，61 普通 / 66 罕见 / 18 稀有 / 5 传说） | 齐 |
| 消耗品 | 22 塔罗 + 12 行星 + 18 幻灵 = 52 | 52（`Consumable.kt` 三个列表） | 齐 |
| 代金券 | 32 | 32（`Voucher.kt`） | 齐 |
| 标签 | 24 | 24（`GameEngine.kt` `Tag`） | 齐 |
| Boss 盲注 | 28 | 28（`Blind.kt` `BossModifier`） | 齐 |
| 牌组 | 15 | 15（`DeckType.kt`） | 齐 |
| 赌注 | 8 | 8（`Stake.kt`） | 齐 |
| 挑战 | 20 | 20（`Challenge.kt`） | 齐 |
| 牌型 | 12（含 3 隐藏） | 12（`HandType.kt`，含五条 / 同花葫芦 / 同花五条） | 齐 |

所以"还缺什么"的答案不是"缺内容"，而是三层：

1. **流程的边角**：原版每次操作都能看到"系统在做什么"，本作有几处是黑箱。
2. **长线目标**：原版靠成就、解锁、每日挑战把玩家留在牌桌上，本作一局打完就没了。
3. **演出密度**：原版每个动作都有反馈，本作有反馈但缺"动作本身"。

---

## 1. 流程边角（每局都会碰到）

### 1.1 手牌不能一键排序 — 缺

原版牌桌右下有两个排序按钮（按点数 / 按花色），一键把 8 张牌理顺。
本作只有长按拖拽单张（`ui/CardWidget.kt` `detectDragGesturesAfterLongPress`），
`GameEngine.kt:690` 的注释写着"上一版只能整体排序，等于把这条策略剪掉了"，
于是改成拖拽 —— 但**一键排序本身没有补回来**。

影响：每手开局都要手动理牌，手表上拖 8 张牌是体力活。
补法：引擎加 `sortHand(by: Rank/Suit)`，牌桌加一个小按钮，成本低。

### 1.2 看不到牌堆和弃牌堆 — 缺

`GameEngine.kt:219` 有 `discardPile: List<Int>`，`289` 有 `drawPile`，
但**没有任何界面能查看它们**。原版点牌堆能看剩余所有牌（含已被改造的牌），
点弃牌堆能看已弃的牌 —— 这是判断"还剩几张红桃"的唯一手段。

影响：同花、顺子的听牌判断只能靠记忆，中后期的构筑决策失去依据。
补法：新增一个只读的牌堆浏览页，复用图鉴的网格组件。

### 1.3 没有 Run Info（牌型等级总览）— 缺

本作只在结算面板显示当场牌型的等级（`ui/GameScreen.kt:438` `${p.handType.cn} · ${p.level} 级`）。
原版左侧常驻一个信息面板，列出**全部 12 种牌型的当前等级与筹码/倍率**，
还能看到本局已用过哪些行星牌。

影响：玩家不知道自己"对子已经 5 级了"，行星牌的价值判断失焦。
补法：`levels: Map<HandType, Int>` 已在引擎里（`GameEngine.kt:586`、`792`），
只差一个展示页。

### 1.4 小丑的"售价预览"埋在长按里 — 半缺

`GameEngine.kt` `sell()` 已实现按稀有度/版本折算，出售有二次确认，
但牌桌上没有"这张现在卖多少钱"的常显。原版在选中时直接标在牌角。

### 1.5 打出的牌没有"飞过去"的过程 — 缺

出牌区本身做得不差：牌停在那里，逐张弹起、计分完变暗、正在计分的放大加金边，
还有 `ChipBurst` 筹码粒子（`ui/GameScreen.kt:458` 起）。缺的是**前一帧**：
手牌消失与出牌区出现之间没有位移，牌是"跳到"那一格的。

原版是牌从手牌位置（含倾角与偏移）沿一条弧线飞到出牌区，落定时带一点回弹。
这一步在 1.4 英寸屏上尤其重要 —— 没有它，玩家眼睛要重新找焦点。

弃牌同样：`discardPile` 只接受数据（`GameEngine.kt:829`），界面上没有任何"牌散开"的表现。

### 1.6 商店买入没有"飞向槽位" — 缺

买小丑时直接出现在 `JokerStrip` 末尾（`ui/GameScreen.kt:275`），没有从商品卡飞到槽位的过渡。
原版这一步有明确的位移 + 音效，是"我买到了"的确认感来源。

## 2. 长线目标（决定玩多久）

### 2.1 没有成就系统 — 缺

`SaveStore.kt` 只有 `bestAnte / bestHand / runs` 四个字段（`56`–`80` 行），
没有成就定义、没有达成判定、没有展示页。原版有 20+ 成就，且部分成就解锁小丑。

检索确认：`grep -rni "achiev|成就"` 在 `SaveStore.kt`、`ui/` 下无命中。

### 2.2 没有每日挑战 / 种子输入 — 缺

`GameEngine(seed: Long = System.currentTimeMillis())`（`269` 行）已支持固定种子，
`Challenge.kt` 的 20 个预设也走 `resetRun(deck, seedOverride = c.seed)`（`537` 行），
但**玩家无法自己输入种子**，也没有"今天的种子"这种每日模式。

`grep -rni "daily|每日"` 全项目零命中。

### 2.3 小丑与牌组没有"解锁条件" — 缺

原版的小丑要满足条件才进池（例如"打出 1000 筹码的一手"），牌组要打通才解锁。
本作 `Jokers.shopPool` 默认全开，`DeckType` 15 个也全开。
唯一的解锁层是赌注（`SaveStore.maxStake` + `unlockNextStake`）。

后果：第一局就能抽到传说小丑，进度曲线是平的。

### 2.4 统计只有三个数，没有页面 — 半缺

`recordRun(ante, hand)` 只累加最好底注、最好单手指、局数。
原版统计页有：总胜率、各牌组胜场、最长连胜、最常见死因、总弃牌数等十余项。
本作这些数据**根本没有采集**（引擎里没有对应计数器）。

### 2.5 没有"本局回顾"— 缺

`RunSummary`（`GameEngine.kt:123` 附近）只服务结算页的一次性展示，
没有落盘。玩家无法回看上一局拿了哪些小丑、死在哪一关。

## 3. 演出密度（决定"爽不爽"）

| 环节 | 原版 | 本作 | 状态 |
|---|---|---|---|
| 发牌 | 逐张飞入 | 逐张落下，42ms 错峰 | 有 |
| 出牌 | 飞向出牌区 | 瞬时消失 | 缺 |
| 弃牌 | 散向弃牌堆 | 瞬时消失 | 缺 |
| 单张小丑触发 | 跳一下 + 数字飞出 | `pulseIndex` 放大（`GameScreen.kt:282`） | 半 |
| 倍率结算 | 数字弹跳、`×Mult` 飞字 | 数字滚动（`628` 行，240ms） | 半 |
| 筹码累加 | 逐个数字跳 | 同上 | 半 |
| 打破 Boss | 全屏特效 | 震屏 + 闪光（`ShakeBox`） | 半 |
| 商店买入 | 飞向槽位 | 直接出现 | 缺 |
| 卖小丑 | 飞走 + 金币动画 | 直接消失 | 缺 |
| 通关 | 长演出 | 结算页 + 标题 | 半 |

"半"的意思是：有反馈，但只有一个通道（放大或变色），没有原版那种
**位移 + 数字 + 音效三通道同时发生**的叠加感。

## 4. 平台层（手表独有，原版没有，但用户会期待）

### 4.1 没有 AOD / 常亮 — 缺

`grep -rni "ambient|AlwaysOn|isAmbient"` 全项目零命中。
抬腕看牌、放下手腕变暗，是手表的基本行为；本作放下手腕就整块黑。

### 4.2 表冠只覆盖手牌 — 半缺

`onRotaryScrollEvent` 只在 `ui/GameScreen.kt:225` 一处，用于手牌光标。
商店列表、图鉴分页、设置档位都不响应表冠 —— 手表上最自然的输入方式只用了十分之一。

### 4.3 Tile 已补，Complication 仍缺 — 半缺

第九轮补上了手表卡片（`tile/JokerTileService.kt`）：底注 / 分数 / 目标 / 进度条 /
剩余出牌，轻触回牌桌。这一项原本是"没入口"，现在有了"随时被提醒回去玩"的手势。

仍缺的是**表盘上的 Complication**（把"当前底注"或"最好成绩"做成表盘小部件），
以及息屏（AOD）下的卡片 —— 卡片和界面一样，放下手腕就整块黑。

### 4.4 只有中文 — 缺

`app/src/main/res/values/strings.xml` 单份，界面文案 100% 硬编码在 Kotlin 里
（`Type`/`T(...)` 调用直接传中文字面量）。原版有 11 种语言。

### 4.5 没有无障碍语义 — 缺

`CardWidget`、`JokerStrip` 都是 Canvas 绘制，没有 `contentDescription` /
`semantics`。TalkBack 用户看到的是"按钮"，不知道是哪张牌。

## 5. 内容质量（数量齐了，但成色有差）

### 5.1 牌型层完整，但注释写错了

原版 12 种（含 3 隐藏：五条 / 同花葫芦 / 同花五条）。本作 `HandType.kt` 同样是 12 项，
数值也一致（五条 120/12、同花葫芦 140/14、同花五条 160/16）。

但文件头注释写的是"13 种牌型（含 3 种隐藏牌型）"，枚举里只有 12 条。
不影响运行，但会误导后来读代码的人去找一个不存在的牌型。

> 记录一句：本轮核查我一度把这条判成"缺三个隐藏牌型"，是被注释带偏的。
> 说明注释与实现不一致本身就是一种缺陷。

### 5.2 稀有度分布有偏差

| 稀有度 | 原版 | 本作 |
|---|---|---|
| 普通 | 61 | 61 |
| 罕见 | 64 | 66 |
| 稀有 | 20 | 18 |
| 传说 | 5 | 5 |

合计都是 150，差异只在中间两档：罕见多 2 张、稀有少 2 张。
传说档对上了，这是关键的一档。

### 5.3 商店没有按底注收窄稀有度

`Jokers.rollOne`（`Joker.kt:539`）按 `rarity.weight` 固定加权抽（70 / 25 / 5），
**与当前底注无关**。原版这条曲线是随底注走的：第 1–2 关稀有档权重为 0，
第 3–4 关很低，第 5 关起才回到 5%。开局几关"抽到的都是普通牌"这种朴素感，
是节奏的一半。

有一处是对的做法，值得记下来：传说小丑被排除在 `shopPool` 之外（`Joker.kt:531`），
只能通过「灵魂」幻灵牌以 0.3% 的概率出现（`BoosterPack.kt` cameo 分支）——
和原版一致，而不是让传说进商店明码标价。

### 5.4 挑战是"参数改写"，不是"脚本"

`Challenge.kt` 每条规则都映射到已有参数（牌组/赌注/起始钱/目标倍率/常驻 Boss）。
原版部分挑战是**专属规则**（例如"每回合只能打一张牌"、"小丑全部变成负片"），
无法用参数表达。这是结构性的近似，不是遗漏。

### 5.5 美术是几何图形，不是像素画

`ui/Art.kt` 用 Canvas 画牌面与小丑头像（`JokerFace`）。这是法律上的必要选择
（不复制原作素材），但也意味着**"看起来像 Balatro"这件事永远达不到**。
可改善的方向是给 150 张小丑各配一套几何母题（现在很多是同一套脸的变体），
而不是追求还原。

### 5.6 音乐是单段循环

`fx/Music.kt` 只有一段 8 小节，靠改速度区分场景。原版有多首完整曲目，
且会随底注推进叠加声部。

### 5.7 音效 14 种，原版数十种

`fx/Feedback.kt` 的 `Sfx.Kind` 枚举是 14 项，全部代码合成。
缺的主要是"环境层"：牌桌的纸张摩擦、硬币堆叠、UI 悬停的极轻反馈。

---

## 6. 不打算补的（有意为之，不是遗漏）

| 项 | 原因 |
|---|---|
| 原作美术/音频素材 | 版权。全部代码绘制与合成 |
| 全屏大段动画 | 1.4 英寸屏 + 电池，长动画会拖慢节奏 |
| 完整曲库 | 手表外放场景有限，单段循环足够 |
| 14 种语言的本地化 | 当前只服务中文用户；文案已集中，需要时可抽 |

---

## 7. 如果只再走一轮，按这个顺序

**第一批（改动小、每局都能感知）**
1. 手牌一键排序（引擎 + 一个按钮）
2. 牌堆 / 弃牌堆浏览页
3. Run Info：12 种牌型的等级与筹码倍率
4. 出牌、弃牌飞出动画

**第二批（决定留存）**
5. 成就系统（20 条，达成解锁小丑）
6. 统计页（补齐计数器 + 展示）
7. 种子输入 + 每日挑战
8. 商店稀有度按底注收窄

**第三批（平台质感）**
9. AOD 常亮
10. 表冠覆盖商店 / 图鉴 / 设置
11. 无障碍语义（牌面与按钮的 `contentDescription`）
12. Tile / Complication
