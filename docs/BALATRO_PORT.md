# 腕上小丑 · WristJoker

> 把《小丑牌 Balatro》的玩法搬到三星 Galaxy Watch7 上的原生 Wear OS 移植实验。

本文记录了从「看到一条视频」到「装进手表」的完整决策链：识别游戏、评估可行性、放弃封装、重写核心、重设计交互、验证数值、构建产物。所有结论都标注了依据，没把握的地方会明说。

## 3. 为什么不做「APK 封装」

最常见的"移植"做法是拿现成 APK 套个壳。这里三个理由都不成立：

1. **法律上不成立**。Balatro 是商业付费游戏，APK 再分发是侵权。它的 Lua 源码被社区逆向整理过（供 mod 研究），但逆向工程文档不能作为再分发的许可。
2. **技术上不成立**。原作是 LÖVE 2D 运行时 + 手机横屏 1080p 布局 + 大量图集纹理。Galaxy Watch7 只有 **2GB RAM / 1.3~1.5 英寸圆屏**，LÖVE 的 OpenGL ES 上下文和纹理内存在这个尺寸上跑不稳；更致命的是**它的 UI 全是为矩形大屏设计的**，圆形 1.3 寸屏上牌桌、卡牌列、商店三栏全部错位，触摸目标小到无法命中。
3. **体验上不成立**。就算强行侧载成功，得到的是一个"能启动但没法玩"的窗口 —— 这不算移植。

**所以选了第四条路：原生重写。** 用 Kotlin + Compose 从头实现玩法，只为圆屏和表冠重新设计交互。玩法机制本身不受版权保护，图形全部由代码绘制，不使用原作任何素材文件。

>
> **2026-11-15 追加**：用户要求「改回原本的 52 张牌面数字显示 + 更精美的 UI + 游戏流程全部借鉴小丑牌 + 开始/结束界面」。三件事一起做：

## 5. 移植了什么

### 5.1 完整保留的核心循环

| 机制 | 实现情况 |
|---|---|
| **单局循环：主菜单 → 盲注选择 → 打牌 → 结算 → 商店 → 下一关** | ✅ 6 个界面，`Phase` 枚举驱动 |
| **盲注选择与跳过**（前两档可跳，换 $3 现金） | ✅ Boss 不可跳，与原作一致 |
| **结算页逐项入帐**（击败奖励 / 剩余出牌 ×$1 / 利息） | ✅ 停在结算页，点「收下」才加钱 |
| 52 张标准牌、8 张手牌 | ✅ |
| 每关 4 次出牌 / 3 次弃牌 | ✅（Boss「针」为 1 次出牌，「水」为 0 次弃牌） |
| 选 1~5 张出牌，判最强牌型 | ✅ 13 种牌型全实现 |
| 得分 =（基础筹码 + 牌面筹码）× 倍率 | ✅ 含小丑逐张结算 |
| 小丑牌提供加成 | ✅ 18 种（原作 150+） |
| 8 关（Ante）渐进，目标分查表 | ✅ 与官方表逐项一致 |
| Boss 盲注带负面效果 | ⚠️ 4 种（原作 20+） |
| 金钱：过关奖励 + 剩余出牌 + 利息 | ✅ 利息每 $5 得 $1，上限 $5 |
| 商店买小丑、卖出、重掷 | ✅ 3 件商品；卖出返半价（至少 $1）；重掷 $5 起每次 +$1 |
| 牌型等级成长 | ⚠️ 用「击败 Boss 随机牌型 +1 级」替代行星牌 |

### 5.2 牌型基础值（与原作逐项核对）

判定顺序由强到弱，先命中先返回 —— 这条规则决定了 `K K K K 2` 永远是四条而不是同花。

| 牌型 | 筹码 | 倍率 | 每级 +筹码/+倍率 |
|---|---|---|---|
| 高牌 High Card | 5 | 1 | +10 / +1 |
| 对子 Pair | 10 | 2 | +15 / +1 |
| 两对 Two Pair | 20 | 2 | +20 / +1 |
| 三条 Three of a Kind | 30 | 3 | +20 / +2 |
| 顺子 Straight | 30 | 4 | +30 / +3 |
| 同花 Flush | 35 | 4 | +15 / +2 |
| 葫芦 Full House | 40 | 4 | +25 / +2 |
| 四条 Four of a Kind | 60 | 7 | +30 / +3 |
| 同花顺 Straight Flush | 100 | 8 | +40 / +4 |
| 五条 Five of a Kind | 120 | 12 | +35 / +3 |
| 同花葫芦 Flush House | 140 | 14 | +40 / +4 |
| 同花五条 Flush Five | 160 | 16 | +50 / +3 |

计分细节也照搬了原作的两条容易搞错的规则：

- **只有"参与牌型"的牌才计筹码**。打 `K♠ K♥ 9♦ 4♣ 2♥` 时，9/4/2 只是陪跑，不贡献筹码。
- **皇家同花顺不是独立牌型**，它是同花顺的特例（A 高），共用一个等级。

## 6. 界面为什么长这样

### 6.1 圆屏是硬约束，不是审美选择

可用区域是半径 96dp 的圆。**越靠上下边缘，可用弦长越短**：

| 距圆心 | 可用宽度 |
|---|---|
| 0dp | 192dp |
| ±50dp | 164dp |
| ±70dp | 131dp |
| ±77dp | **115dp** |

屏幕本身有 192dp 宽，但最上/最下一行只剩 115dp。所以这一页**不用 `fillMaxWidth`**，而是每行单独限宽：

| 行 | 宽度 | 该行最窄处可用 |
|---|---|---|
| 状态（A1 / 小盲 / $4 / 丑0） | 112dp | 115dp |
| 分数（1860 / 3000） | 148dp | 155dp |
| 进度条 | 162dp | 170dp |
| 牌型提示（计分公式） | 160dp | 168dp |
| 手牌 2×4 | 162dp | 164dp |
| 操作按钮 | 106dp | 110dp |

垂直合计 144dp，居中后上下各留 24dp。

**为什么是 144dp 而不是更满**：手牌区在 y≈+43dp 处，162dp 宽所需弦长 164dp，余量只有 2dp。真机字体行高比 dp 估算多 1dp 时，整页就会长到 150dp，最远角升到 93.6dp；多 2dp 则是 95.2dp，仍在 96dp 以内。这条余量是按「+2dp/行」的容差反推出来的，不是拍脑袋留白。

其余五个界面按同一条判据（元素四角到圆心 ≤ 96dp）约束在 122dp 竖带里：

| 界面 | 最宽元素 | 总高 | 最远角 |
|---|---|---|---|
| 开始 | 按钮 104dp | 133.7dp | 84.7dp |
| 盲注选择 | 卡片 122dp | 129dp | 88.8dp |
| 结算 | 明细 112dp | 144dp | 90.6dp |
| 商店 | 卡片 122dp | 143dp | 94.0dp |
| 结束 | 按钮 122dp | 141dp | 93.2dp |

六个界面的逐元素四角半径见 `verify-report.md` §14，渲染对照图见 `preview/screens-all.png`。

### 6.2 手牌为什么是「横版 2×4」

原版手牌是竖排卡牌 + 横向滚动。到了手表上这条走不通：

- 竖版比例（0.7）下，8 张牌铺到 192dp 宽时每张只有 22dp —— 点数看不清。
- 横向滚动和 Wear OS 的「左滑返回」手势直接冲突，误触率高。
- 滚动时看不全手牌，玩家没法做全局判断，而这是这个游戏的策略核心。

**改成横版卡（36.75×25dp）+ 2 行 4 列，一屏全见。** 代价是牌变小变扁，好处是选牌零滚动。对一个"只看点数和花色"的游戏，这笔交易划算。

这个尺寸直接决定了牌面必须是矢量：88×124 的位图按宽度铺满会是 36.75×51.8dp，超出槽位 27dp，只能从顶部裁 —— J/Q/K 的人像刚好被截在人脸以下。改成逐格绘制的点阵后，左上角索引块（点数 + 小花色）占 9.6dp 高，中央花色 15.5dp，都在槽位内完整呈现。

### 6.3 交互

| 操作 | 方式 |
|---|---|
| 选牌 / 取消 | 点牌 |
| 表冠 | 旋转移动金色光标（`onRotaryScrollEvent` + `FocusRequester`） |
| 出牌 | 底部左按钮 |
| 弃牌 | 底部右按钮 |
| 看小丑牌 | 点顶部「丑 N」徽章 |
| 震动反馈 | 出牌 / 弃牌 / 购买时 `LongPress` 触感 |

按钮只有 50×26dp —— 这比 Wear 推荐的 48dp 触摸目标高度小。原因是圆屏最下沿只剩 115dp 宽，两个按钮加粗就放不下。实测手指点在圆形表盘底部时接触面积足够，但这确实是妥协，不是最优解。

### 6.4 美术：借鉴原作视觉语言，全部重绘

用户确认「可直接借鉴原作美术和牌面」后，界面从自创的深夜靛蓝改成高保真对齐 Balatro。色值不是凭印象调的，取自原作公开本地化脚本的 `G.C` 常量表：筹码蓝 `009DFF`、倍率红 `FE5F55`、金钱金 `F3B958`、稀有度蓝/绿/红、赌桌墨绿 `374244`、花色 `FE5F55 / 374649 / 424E54`。

| 元素 | 做法 |
|---|---|
| 牌面 | 米白纸底 + 硬描边 + 内框 + 45° 纸纹；左上点数、中央 Path 花色、右下蓝色筹码值 |
| 牌背 | Bicycle 式交叉斜网格 + 中心菱形 + 金色圆芯 + 白双线边框 |
| 数字 | 5×7 点阵逐格 `drawRect`，等宽机械计数器感 |
| 小丑牌 | 稀有度色硬边框 + 8×8 像素头像，18 种各一张不同的脸 |
| 背景 | 深墨绿毡 + 旋转六边形漩涡 + 固定噪点 + 径向暗角 |
| CRT | 每 3dp 一条扫描线，铺最上层但不注册 pointerInput，触摸穿透 |

所有图形在 `ui/Art.kt` 里用 Canvas 画，不含原作图集、字体或贴图；工程 `res/` 也没新增图片（APK 内 16 张 PNG 全部是 AndroidX core 的通知兼容 9-patch）。完整色板、牌面规范与 1:1 样张见 [视觉规范](../../wristjoker-art/ART_BIBLE.md) 与 [样张](../../wristjoker-art/index.html)。

## 7. 数值正确性怎么保证

没有真机、没有模拟器（沙箱无 `/dev/kvm`），所以**用单元测试代替跑通验证**。

33 个 JVM 用例，纯 Kotlin，不依赖 Android：

| 测试类 | 用例 | 覆盖 |
|---|---|---|
| `HandEvaluatorTest` | 13 | 13 种牌型判定 + A 高低 + 四条优先于同花 + 单张出牌 |
| `ScoringTest` | 9 | 计分公式对照官方基础值、乘算顺序、男爵连乘、Boss 封锁、牌型升级 |
| `GameEngineTest` | 11 | 盲注表、开局状态、出牌扣次数、选牌上限、弃牌、商店买卖、整局推进到终态 |

几个特意写进去的边界：

- `A K Q J 2` **不是**顺子（A 不能同时当两头）
- `A 2 3 4 5` **是**顺子（A 当 1）
- `K K K K 2` 判为四条而非同花（牌型优先级）
- 梅花被 Boss 封锁时，牌型判定不变、筹码减少（封锁只影响"谁得分"）
- 「会算分的机器人」穷举 1~5 张全部组合挑最优出牌，所以"能不能过关"这类断言不依赖牌运

```
GameEngineTest         tests=11  failures=0
HandEvaluatorTest      tests=13  failures=0
ScoringTest            tests=9   failures=0
合计 33 个用例，失败 0
```

## 10. 已知限制（如实）

1. **没有在真机上跑过**。沙箱无 `/dev/kvm`，模拟器起不来；布局用「按真实 dp 坐标 1:1 渲染 + 圆内切边数值校验」验证，逻辑用 115 个单测验证。真机上仍可能出现字体行高差异导致的文字被裁。
2. **每关重洗牌堆**。原作跨关连续、可以记牌算牌；这里每关重置，策略深度低于原作 —— 这是为了让"牌越打越少"的手感问题不出现。
3. **塔罗要选牌，只能在打牌阶段用**。商店里只能用行星牌和不需选牌的塔罗。
4. **没有小丑换位**。结算顺序＝购买顺序，原版的拖拽调整在这里没有等价交互。
5. **字体放大不安全**。所有行都是固定 `Modifier.height()`，系统 `fontScale` 调大时文字会被裁而不是撑高——几何不会切边，但可读性会掉。
6. **音效与震动未校准**。合成参数与 amplitude 值都是按物理直觉定的，没有在真机扬声器/马达上听过。
7. **debug 签名**。仅用于侧载验证，不能上架，也不能覆盖安装正式版。
8. **误触退出**：Wear OS 左滑返回手势仍然生效，游戏中从屏幕左缘滑动会退出。没做手势拦截（会与选牌冲突）。

## 11. 想继续做的话

按收益从高到低：

1. **真机验证** —— 找一台 Watch7 侧载，重点看字体行高与音效听感。若最上/最下行贴着圆边，优先调 `GameScreen` 行 A 的宽度（已从 118 收到 110）与手牌 `rowHeight`。
2. **音效与震动校准** —— `Sfx.render()` 里的频率/包络、`Haptics.tap()` 的 amplitude 都是常数，改起来只动几个数字。
3. **小丑换位** —— 面板里长按拖动，或者"点 A 点 B 交换"，后者在手表上更好点。
4. **开包时的第二层选牌** —— 幻灵/塔罗/标准包已全部做完（§14），但原版开包会另发一手牌供选牌，手表上折成「拿走后先进消耗品槽、牌桌阶段再用」，与原版选牌体验仍有差异；要完全对齐需要一层整屏选牌页。
5. **更多 Boss** —— `BossModifier` 加枚举 + `blocks()`/`spec()` 分支，改动面很小；难的是那些需要"牌背朝上""强制选中"的效果，圆屏上没有第二层信息区。

## 12. 2026-11-16 改造：完整机制 / 自动存档 / 打击感 / 原版布局

四条反馈逐条落地。

### 12.1 「没有完整的机制」

上一版的问题不在内容少，而在**没有构筑曲线**：塔罗缺失就没有牌面改造，行星缺失就没有牌型升级，玩家每一手的期望值恒定 —— 那就退化成"打牌比大小"，不是 Roguelike。

| 机制 | 原作 | 上一版 | 本版 | 落点 |
|---|---|---|---|---|
| 消耗品 | 塔罗 22 + 行星 12 + 幻灵 18 | — | 塔罗 14 + 行星 12，2 槽 | `Consumable.kt` |
| 牌型等级 | 12 种可升级 | 有字段无来源 | 行星牌升级 + 独立等级页 | `useConsumable` / `LevelTab` |
| 卡牌增强 | 8 种 | — | 8 种 | `Card.Enhancement` |
| 蜡封 | 4 种 | — | 3 种 | `Card.Seal` |
| 版本 | 4 档 | — | 4 档，牌与小丑通用 | `Card.Edition` / `JokerInst` |
| 小丑 | 150 张 | 18 张 | 37 张，加权抽取（§13.2 再扩到 101） | `Joker.kt` |
| 代金券 | 32 张 | — | 8 张 | `Voucher.kt` |
| 标签 | 24 种 | — | 6 种 | `Tag.kt`（`Voucher.kt` 同文件） |
| Boss 效果 | 23 种 | 4 种 | 13 种 | `BossModifier` |
| 牌组 | 15 种 | — | 8 种 | `DeckType.kt` |
| 无尽模式 | 有 | — | 有，Boss 按关号循环 | `continueEndless` |

**为什么是这些数量，不是原作的完整数量**（这是 2026-11-16 当时的取舍）：每多一种机制就多一层要在 122dp 宽的界面里解释自己。当时裁掉的是"需要第二层信息区才能理解"的部分 —— 幻灵牌（生成/复制消耗品，要一个 3 层菜单）、负片版本（不占槽位，和"槽位 +1"在手表上没有可见差别）、依赖全局计数器的成长小丑（看不见它长大了多少）。**2026-11-20 第三轮（§14）已把幻灵 18 张、负片版本、成长传奇、4 种蜡封、5 类补充包全部补齐**；上表「本版」列是当时的快照，不是当前状态。

**小丑效果重写成 4 个钩子**（`chips` / `addMult` / `xMult` / `money`），按摆位从左到右依次调用。这让「加算放前面、乘算放后面」成为可优化策略，单测把 12× vs 8× 钉死了。

**石头牌与万能牌**是两个容易被忽略但很影响手感的规则：

- 石头牌没有点数没有花色，**不参与牌型判定但总是计分**（+50 筹码）。`HandEvaluator` 先把石头牌摘出来单独判型，再拼回 `scoringCards`。
- 万能牌在同花判定里当任意花色。实现是 `effectiveSuit` 返回 `null`，`isFlush` 只看"非万能牌是否同花色"。

### 12.2 「没有自动存档」

- **格式**：手写行式文本，`key|value`，值内 `,` 分元素、`~` 分子字段。**不用 JSON** —— `org.json` 在 JVM 单测里是空壳，一调就抛 `Stub!`，而存档往返恰恰最需要反复测。
- **触发**：每次有效操作 `apply()` 一次 + `onStop` 强制落盘 + 结束态清空并记录历史成绩。存档串约 1.4 KB。
- **恢复**：`onCreate` 先 `restore()`，主菜单显示「继续 · A3 · 小盲注 · $17」。
- **容错**：坏行只丢那一行；缺字段回落默认值；版本号超前拒绝加载；主表不存在的牌 id 从三个堆里剔除。
- **边界**：存档点落在「这一手已达标但动画没播完」时，`restore()` 补一次结局，否则会卡在 PLAYING 既出不了牌也过不了关。

`SaveCodec` 与引擎一起在 JVM 单测里跑了往返与 7 种坏数据。

### 12.3 「缺少原版的打击感」

原版爽的不是最终数字，是**把数字怎么来的逐条演出来**。

- `Scoring.compute` 现在返回 `List<ScoreStep>`：每一步带来源（牌型/某张牌/手中牌/某小丑）、文案、执行后的 `chips` 与 `mult`。
- `GameScreen` 按 78ms（加算）/145ms（乘算）逐条播放，结算带左边"谁给了多少"、右边 `chips × mult` 实时值。
- **引擎不在出牌后立刻切阶段**：结局挂在 `pendingOutcome`，UI 播完动画调 `resolvePending()`。否则一达标就跳走，玩家看不到自己怎么赢的。
- 乘算步整屏抖 2dp（三段衰减 260ms）。
- 4 档震动：8ms/55 → 14ms/110 → 22ms/175 → 38ms/255。
- 10 个音效**全部代码合成**：正弦/方波/三角/噪声 + 指数包络 + 滑音 + 颤音 → 16bit PCM → 套 WAV 头写进 `cacheDir` → `SoundPool`。APK 内零音频文件，改手感只改常数。
- 玻璃碎裂 1/6、幸运 1/5 走引擎随机源；**预览用 `Random(0)`**，否则"看一眼预估分"会改变牌碎不碎。

### 12.4 「借鉴原版 UI 布局再适配手表」

| 原版（PC 横屏） | 这里（216dp 圆屏） | 高 | 宽上限 |
|---|---|---|---|
| 左上 底注/金钱 | 行 A | 13 | 110 |
| 左栏竖排 5 小丑 | 行 B 左段（5×15dp 横排） | 15 | 132 |
| 右栏竖排 2 消耗品 | 行 B 右段（2×15dp + 分隔条） | ↑ | ↑ |
| 顶部 Boss + 分数 | 行 C 点阵累计分 | 18 | 142 |
| 顶部进度条 | 行 D 进度条 + 目标 | 6 | 150 |
| 中部 出牌区 / 公式 | 行 E 结算带 | 17 | 154 |
| 底部 手牌 | 行 F 2×4，35.5×20dp | 44 | 154 |
| 底部 出/弃牌 | 行 G | 22 | 106 |
| | **合计** | **148** | |

两条竖栏折成一行是这轮最关键的决定：竖排 5 小丑要 100dp 高，在 148dp 预算里等于砍掉手牌区；横排后徽章 + 分隔 + 消耗品共 121dp，正好塞进 y=-59 那档的 157dp 弦长。

行 A 从 118dp 收到 110dp 是纯几何原因：它在 y=-74，四角半径 94.6dp 只剩 1.4dp 余量，收到 110dp 后降到 92.2dp。

### 12.5 取舍

- **塔罗要选牌，只能在 PLAYING 阶段用**。商店里只用行星牌和不需选牌的塔罗（隐者/节制/审判/命运之轮）。手表上没有第二层选牌界面，与其做一个 122dp 宽的弹窗，不如把限制写在面板提示里。
- **不做小丑换位**。原版靠拖拽调整结算顺序；手表上拖拽与返回手势冲突，而"点一下卖掉再买回来"会亏一半钱。这一版没有换位，摆位策略只能在购买顺序里体现。
- **标签即时结算，不做待生效队列**。122dp 宽的界面上没法展示"我身上挂着什么"，队列在这里等于让玩家失忆。

## 13. 2026-11-15 再改造：商店三段 / 打击感五层 / 原版分区 / 详情页

第二轮反馈的四点，逐条对应到设计决策。

### 13.1 商店为什么必须拆成三段

原版一屏能同时看到 2 个商品 + 2 个补充包 + 1 张券 + 自己的小丑。122×70dp 的圆屏做不到，但"做不到"不等于"可以少给"——补充包是塔罗/行星/改造扑克的第二条通道，删掉它等于把构筑的一半路径砍了。

> **第四轮修正**：这一版先做成了四个分页（商品/卡包/代金券/我的），代价是
> **玩家不知道有卡包**——内容在，但躲在第二个标签背后。这条已被推翻：现在四段
> 同屏摊开，见 §15.1。分页方案在这里保留为演进记录。

当时的做法是**同一屏内的四个分页**：商品 / 卡包 / 代金券 / 我的。每个分页一行 28dp，
一屏能放 2 行多一点，靠滚动看全。分页标签 13dp 高、四个平分 122dp。

重掷只重抽商品位：`reroll()` 先存下 `boosters` 与 `voucher`，`rollShop()` 之后原样放回。这和原版一致——否则攒钱重掷就能刷出一堆巨型小丑包，经济曲线会塌。

### 13.2 101 张小丑的构成

| 类别 | 数量 | 代表 |
|---|---|---|
| 固定 / 条件加成 | 62 | 小丑、半个小丑、抽象小丑、旗帜 |
| 花色点数联动 | 18 | 贪婪/色欲/愤怒/暴食、学者、斐波那契 |
| 手中牌与牌堆联动 | 11 | 男爵、钢铁、石头、蓝色小丑 |
| 乘算爆发 | 9 | 黑板、方尖碑、照片、黄昏 |
| 复制型 | 2 | 蓝图（复制右侧）、头脑风暴（复制最左） |
| 传奇 | 5 | 卡尼奥、特里布莱、约里克、希科、佩尔克 |

稀有度权重照原版 70/25/5，传奇 0。`rollOne` 是真的按权重累计抽，不是 `shuffled().take(n)`——上一版那个写法等于把稀有度做成装饰。

传奇的效果全部挂在**引擎已有统计量**上（毁掉的人头牌数、累计弃牌数、本手 K/Q 数、`spec.modifier`、商店回合结束），不为每张牌单独加一个玩家看不见的计数器。原版那种"角落里的小数字"在手表上没有位置。

### 13.3 打击感是五层，不是一个大动画

原版的反馈是叠加出来的：牌弹起 + 数字滚动 + 屏幕震 + 飘字 + 音高上行，五件事在同一秒里发生。少任何一层都会"不够爽"，但只做一层加幅度会更假。

手表上的预算：牌弹跳用 `spring(0.42, 1400)`（阻尼偏低，弹两下就停）；数字用 120ms 补间；震屏按得分量级分 1~5dp 五档，而不是固定幅度；飘字 420ms 上移 9dp；音高 `2^(2i/12)` 逐张升半音。

`ScoreStep` 加了一个 `EDITION` 来源：箔/全息/多彩各自一步。这不是为了好看，是因为"我这张多彩牌亮了"必须是一个可被看见的事件。

### 13.4 七行分区与原版的对应关系

原版是「左上状态 / 顶部小丑 / 中部出牌区 / 右上筹码倍率 / 底部手牌 / 底部按钮」的六区。圆屏上折成七行，多出来的那一行是进度条（原版的目标分在顶部，圆屏顶部放不下两个数）。

关键改动是**加了出牌区**。上一版把出牌区压成一行结算带，牌打出去就没了——玩家看不到"我打出的牌正在逐张计分"，那是打击感缺失的真正原因。现在 5 张 28×20dp 的牌停在那里逐张弹起，算完的变暗，正在算的放大加金边。

> **第四轮修正**：七行的**宽度不再写死**，改成按各自高度的弦长取值；手牌也从 2×4 网格
> 改成了单排扇形。详见 §15.2。上面那张 110/132/154/156/150/154/106 的固定宽度表
> 已经作废，只作为演进记录保留。

### 13.5 详情页与两次确认

122dp 宽的行里，小丑名字 8.5sp、说明 6sp，长效果必然被裁。原版靠 hover tooltip 解决，手表没有 hover，只能给一个详情层。

详情层是 122dp 宽、居中、从上到下：40dp 大图 → 名字 → 稀有度·价格 → 3 行正文（7sp，固定 28dp 高）→ 动作按钮。商店商品、自己的小丑、消耗品都能点开。

卖出的两次确认不是防呆，是圆屏的物理约束：122dp 宽的圆里，最外侧的点击目标离圆心 90dp 以上，误触率远高于矩形屏。第一次点击把按钮文字换成「再点确认卖出」并保持 2.2 秒，超过就复原——既不会让玩家卡在确认态，也不会一碰就卖。

### 13.6 与 §12.5 取舍的差异

- 塔罗仍然只能在 PLAYING 阶段选牌使用，但**补充包里的塔罗可以直接拿走进槽**（包内不再套一层选牌），这条和原版一致。
- 小丑仍然不做拖拽换位，但蓝图/头脑风暴让"摆位"第一次有了实际意义：把蓝图放在男爵左边、把 ×倍率放在 +倍率右边。
- 标签仍是即时结算。

## 14. 2026-11-20 第三轮：上网核对原版后补齐机制 / 打击感 / UI 布局

### 14.1 为什么有这一轮

前两轮都是「照着自己已有的实现判断哪里不够」，用户第二次反馈明确要求**先上网找原版资料，再据此修改**。这一轮先查资料、列出代码与原版的真实差距，再逐项改 —— 不再是自我感觉式的补全。

### 14.2 机制：把「清单数字」真正落到状态机上

扩表本身不难，难的是**让 18 张幻灵的效果真的改状态**。做法是 `ConsumableResult` 一次性返回所有可能的变更，由 `GameEngine.useConsumable()` 统一落账：

| 结果字段 | 引擎动作 |
|---|---|
| `allLevelsUp` | 12 个牌型各 +1 级（黑洞） |
| `spawnCards` | `nextCardId()` 重分配 id 后塞进 `master` / `drawPile`（熟悉者/冷酷/咒语/神秘生物） |
| `destroyRandomHand` | 随机摧毁手牌、同步清四个堆、累计卡尼奥成长计数（献祭 5 张） |
| `convertHandSuit` / `convertHandRank` | 把手牌全改成同一花色 / 点数（印记 / 通灵板） |
| `handSizeDelta` | 累加到持久的 `handSizePenalty`，经 `handSizeBonus()` 跨盲注生效，并随存档 `hsp|` 往返（通灵板 / 外质） |
| `spawnRareJoker` + `moneyToZero` | 生成稀有并**最后**把钱清零，覆盖槽满折价（怨灵） |
| `jokerApocalypse` | 随机留一张、清其余；1 额外复制（生命之符）、2 改成多彩且不复制（咒术） |
| `editionRandomJoker` | 给随机一张小丑加指定版本（外质负片） |

蜡封的两个运行时行为也从「计分给钱」纠正为原版时机：**紫蜡封**在 `discard()` 里按被弃张数生成塔罗；**蓝蜡封**在 `clearBlind()` 里按 `lastHandType` 生成对应行星（`Consumables.planetFor`），新增 `lastHandType` 在每次出牌时记录、每关开始时清空。

### 14.3 打击感：屏幕层 / 粒子层 / 协同层

```
JuiceBackdrop (全屏 Canvas，叠在牌桌下，不占任何行高)
├── CRT 扫描线：常驻 alpha .035，结算瞬态升到 .11
├── 背景色脉冲：按 handTypeColor() 取牌型色，结算时 alpha .15
└── 达标闪白：flash 计数触发，280ms 淡出
```

配合 `RollingDigits`（逐位 stagger 停格）、`ChipBurst`（9 粒子放射 + 拖尾）、`PlayedCard`（±3° 稳定随机倾斜）、`JokerStrip(pulseIndex)`（谁在给分放大谁）、`Sfx.KACHING` / `Sfx.BASS`（14 个代码合成音色）。**关键约束**：全屏效果必须走叠层而非新增行，否则圆屏四角 ≤96dp 的判据会立刻被打破 —— 这也是 10 界面几何校验仍能全 PASS 的原因。

### 15.2 圆屏：从"矩形安全区"改成"弦长版式"

上一版所有行宽度写死成 110/132/154/146/150/154/106dp。这套数字的来源是
「以最窄的那一行（按钮 106dp）为准，其余行都别超过它」—— 于是圆屏 216dp 的直径
只用到一半，左右两大块面积全是黑的。玩家说的"像给圆屏加了个安全区"，指的就是这个。

新做法：一条横带在距圆心 `dy` 处能用的最大宽度，就是那一段的**弦长**。

```
宽 = 2·√(r² − dy²)        r = 108 − 9 = 99dp（内容圆）
```

实现要点（`ui/CircleFit.kt`）：

- `chord(dy)` 取弦长；`INSET = 9dp` 是内容圆到玻璃的余量（5dp 边缘渐暗 + 2dp 弧切 + 2dp 行高溢出）。
- `widths(bands)` 用的是**这一行上下沿里离圆心更远那条边**，不是中心线。用中心线会让高行的四角戳出圆外：
  一行高 `h`、中心距圆心 `dy` 时，四角半径 = `√(r² + dy·h + h²/4) > r`。
  手牌带 42dp 高、`dy=26.5`，用中心线会多出 7dp，正好把牌角顶到玻璃边上。
- `GameScreen.PLAY_BANDS` 与 `ShopScreens.SHOP_BANDS` 是两份纯数据，测试与
  `tools/verify_circle.py` 都直接读它们，不会出现"代码改了脚本没改"。

结果（`tools/verify_circle.py` 实测）：

| 横带 | 上一版 | 现在 | 拿回 |
|---|---|---|---|
| 底注/盲注/手牌 | 110 | 139.0 | +29.0 |
| 小丑+消耗品 | 132 | 161.2 | +29.2 |
| 出牌区 | 154 | 178.8 | +24.8 |
| 筹码×倍率 | 146 | 195.2 | +49.2 |
| 进度 | 150 | 197.9 | +47.9 |

### 15.3 手牌：从 2×4 网格改成单排扇形

原版的手牌是"一手捏着的牌"：沿浅弧摊开、每张略微倾斜、两端下沉，选中的抬起来压到
相邻牌上。这个摆法本身就是信息 —— 一眼能数出手里有几张，也能立刻看出哪张被选了。
2×4 网格把这两点都丢了。

`ui/CardWidget.kt` 的 `HandFan`：

- 每张露出 `cardWidth × 0.72`（25dp × 0.72 ≈ 18dp），牌多时按可用弦长均分，永不溢出圆弧；
- 倾角每张递进 1.7°，两端封顶 ±13°；
- 下沉 `off² × 1.4 / (mid + 0.8)`，最多 4dp；
- 选中的抬起 5dp、`zIndex = 60` 盖住相邻牌；
- 后画的牌盖住前一张的**右段** —— 所以露出来的是每张牌的**左段**。

最后这条决定了一件重要的事：**所有标识都必须画在左侧**。上一版把增强画在右上角、
蜡封画在右下角，扇形一摊开就全被吃掉了 —— 这正是"特殊手牌标识不明显"的机械原因。
现在 `CardFaceArt` 改成：

- 顶部**双层通栏色带**：上层版本（箔/全息/多彩/负片），下层增强（奖励/倍率/万能/玻璃/钢铁/黄金/幸运/石头）；
- 点数索引块整体下移到色带之下；
- 蜡封移到**左下角**，加深色光圈 + 高光点，白牌面、金卡面、银卡面上都能读出来。

### 15.4 节奏与遮挡

| 项 | 上一版 | 现在 |
|---|---|---|
| 每张牌 | 78ms | 170ms |
| 乘算步 | 145ms | 300ms |
| 落桌到第一步 | 0 | 260ms |
| 收尾 | 0 | 320ms |
| 总分停留 | 340ms | 700ms |
| 数字补间 | 120ms | 240ms |
| 一手 5 牌 + 2 小丑 | ≈0.7s | ≈2.6s |

遮挡的根因是飘字：`translationY = -9dp × v` 配上 `padding(top = 18dp)`，整段上浮过程都压在
筹码/倍率那一行上。牌桌每行之间只有 1~2dp 间距，任何纵向位移都会串行。现在改成
`GainPill` —— 贴在出牌带右端的胶囊，只做「放大 → 淡出」，不做位移。

筹码与倍率也各自进了独立方框（蓝盒 / 红盒，中间一个 ×），「= 总分」从这一行撤掉，
交给进度条与结算页。

### 16.3 20 个挑战（`game/Challenge.kt`）

每个挑战 = 固定牌组 + 固定种子 + 一组参数（起始钱 / 出牌 / 弃牌 / 手牌 / 小丑位 /
目标倍率 / 商店加价 / 常驻 Boss）。三条典型：

- **无丑**：`jokerSlotsDelta = -5` → `maxJokers = 0`，商店买不了、开局也送不出；
- **发射**：槽位 0 但 `startJokers = 2`，靠"开局赠送无视槽位"绕过，否则第一天就死锁；
- **美杜莎 / 五张牌 / 定型**：`forcedBoss` 常驻，直接复用已有的 Boss 副作用，不新写规则。

种子固定带来一个实际好处：同一个挑战每次开局的手牌一致，玩家可以复盘

### 16.6 手牌拖拽

`HandFan` 每张牌加 `pointerInput + detectDragGesturesAfterLongPress`：累计横向位移跨过
`露出宽度 × 0.9` 就交换一位。拖拽中索引会变，用 `rememberUpdatedState(i)` 读最新值，
否则第二次拖动会按"按下时"的位置交换，越拖越乱。引擎侧 `moveCard(from,to)` 只动顺序，
不动选中集合（测试钉住）。

### 16.7 这一轮之后仍然缺的

- **Collection 图鉴**：原版可以逐页翻 150 张 Joker / 32 张券的解锁状态，本作没有图鉴页。
- **Stake 解锁顺序**：原版要一档一档打上去，本作八档全开。
- **挑战规则的精确度**：原版有几条依赖隐藏计数器（Typecast 锁牌型、Bram 全人头），
  这里用常驻 Boss / 目标倍率近似，desc 里写的是本作的实际规则。
- **真机手感**：拖拽阈值、扇形倾角、详情页 4 行正文的实机可读性，仍未侧载验证。

## 17. 2026-11-20 第六轮：图鉴、设置、赌注解锁

### 17.1 图鉴（Collection）

原版的图鉴是**唯一的"全集视图"**：150 张小丑、52 张消耗品、32 张代金券、
24 个标签、15 个牌组，逐页平铺，未解锁的显示黑影。它解决的是"我不知道还有
多少东西没见过"这个问题 —— 没有它，150 张小丑在玩家眼里只是一串随机数。

本作实现要点：

```
game/Collection.kt     ← 数据层，全部从既有枚举导出（不新写清单）
  CollectionTab        ← 小丑 / 消耗品 / 代金券 / 标签 / 牌组
  CollectionEntry      ← id（带 j:/c:/v:/t:/d: 前缀）+ 名字 + 副标 + 描述
  Collection.seenCount(tab, seen)
ui/CollectionScreen.kt ← 5 类分页 + 4 列网格 + 底部详情带
```

id 前缀不是随手加的：代金券里有 `rare`，标签里也有 `rare`，不加前缀
`seen` 集合会串。前缀与 `ShopItem.key` **完全同构**（`j:` / `c:` / `v:`），
所以从 `ui.shop` 里收集"见过"的 id 可以直接复用，不需要映射表。

解锁判据做了让步：**见过即解锁**（商店摆过 / 包内开出 / 手里持有），
而不是原版的"拥有过"。手表单局十几分钟，按原版口径图鉴会长期停在 20/150。

存档侧：`seen` 是只增不减的字符串集合，**不进 `wipe()`** —— 图鉴是跨局记录，
清存档不该抹掉它。

### 17.2 设置（Options）

原版 Options 有十来项，手表上只留会改变手感的四项：

| 项 | 档位 | 落点 |
|---|---|---|
| 音效 | 关 / 小 / 中 / 大 | `Sfx.master`（0 / .35 / .7 / 1），`play()` 时乘进音量 |
| 震屏 | 开 / 关 | `Haptics.setEnabled` |
| 扫描线 | 关 / 弱 / 中 / 强 | `CrtOverlay(level)`，强度乘子 0.45 / 1 / 1.7 |
| 结算速度 | 慢 / 标准 / 快 | `GameScreen(speed)`，把 T_DEAL/T_STEP/T_FINALE/T_HOLD 全除以 0.7 / 1 / 1.5 |

全部即时生效、即时落盘 —— 手表上没有"确定/取消"，改完就该听到变化。
音效的 0 档同时 `setEnabled(false)`，省掉 `play()` 里的合成与混音。

### 17.3 赌注逐档解锁

第五轮把八档赌注全开了，这与原作"一档一档打上去"不符。这一轮补上：

```
SaveStore.maxStake          // 已解锁的最高档 ordinal
SaveStore.unlockNextStake(s) // 通关（含进入无尽）时调用
DeckSelectScreen(maxStake)  // 赌注条只在 0..maxStake 循环，到顶提示"通关解锁下一档"
```

一处刻意的放宽：**用任意档通关都能解锁下一档**，不要求"必须用当前最高档赢"。
手表一局十几分钟，逼玩家重复刷低档只会让人退坑。

### 17.4 仍未做

- 图鉴的成就层（原版"用某张牌赢一局"这类解锁）。
- 每档赌注的贴纸与 Boss 池调整（本作只做难度参数）。
- 真机触控验证：网格热区 34dp、设置行高 22dp，都只经 216dp 等比预览确认。

## 18. 灵魂层：声音、发牌、台词

前七轮一直在补"看得见"的东西：版式、机制、内容量。但把原作放在旁边听，
它有一层是界面截图里看不到的 —— 声音、动作过程、以及每张牌的性格。
这三样不占行高，正好是圆屏最该补的地方。

### 18.1 配乐：一段会呼吸的循环

原作的爵士循环不是"背景音乐"，它是**节奏本身**：玩家看牌、算分的速度会被它带着走。
本作之前整局静音，牌桌的空白全靠玩家自己填。

现在 `fx/Music.kt` 在启动时合成一段 8 小节循环：

```
Dm9 → G13 → Cmaj9 → Am9 → Dm9 → G7♭9 → E7 → A7
92 BPM，摇摆八分，走路贝斯 + 反拍电钢 + 鼓刷 + 黑胶底噪
```

- **不用音频文件**：20.87 秒 22kHz 单声道 WAV 约 900KB，代码生成更小、可调，
  还能顺手把速度做成场景参数。
- **场景只改速度**：Boss 0.94（沉下来）、结算/商店 1.06（轻快一点）。换曲子会
  破坏循环的连贯，改速度不会。
- **循环无接缝**：多渲 1.2 小节，尾巴折回开头叠加。

默认档位是「小」。手表外放放音乐是件冒犯的事，玩家得自己往上调。

### 18.2 发牌：让"发"这个动作存在

手牌从"瞬间出现"改成逐张落下：

```
新牌：translationY +20dp、rotationZ +9°、alpha 0、scale 0.94
错峰：index × 42ms（上限 320ms）
时长：240ms，FastOutSlowIn
```

五张牌就是 0.17 秒的"唰唰唰"，与 `Sfx.DEAL` 的噪声摩擦声对得上。
选中抬起（5dp）与拖拽重排保持不变 —— 入场只在 `card.id` 第一次出现时播一次，
重排不会重播。

### 18.3 台词：150 张牌，150 句人话

`game/JokerFlavor.kt` 单独放文案，不动 `JokerDef` 的构造参数（否则 150 处调用全要改）。

> "香蕉迟早会坏，但甜是真甜。" —— 卡文迪什
> "先透支二十，玩了再说。" —— 信用卡
> "每弃十五张，他就长一截。" —— 约里克

详情页底部那行小字原本是"点空白处返回"，有小丑台词时改成台词，没有（消耗品 / 卡包 / 券）
才退回提示。位置没变、行高没变，几何校验不受影响。

四条单测盯着它：每张小丑都有台词、数量与 150 对齐、单句 ≤20 字、不一稿多投。

### 18.4 这一层做到了什么程度

| 维度 | 现在 | 原版 |
|---|---|---|
| 配乐 | 8 小节程序化循环，4 种速度 | 多首完整曲目，随场景切换 |
| 音效 | 14 种合成音，逐张升调 | 采样 + 混音 |
| 发牌 | 逐张错峰入场 | 发牌动画 + 牌堆位移 |
| 出牌/弃牌 | 瞬时消失，补牌入场 | 飞向出牌区 / 散开 |
| 台词 | 150 句 | 150 句 + 手绘插画 |

差距还在，但方向从"补界面"换成了"补过程"。后者才是玩起来像不像原作的分水岭。

## 19. 视觉：一次有纪律的"换皮"

### 19.1 为什么不是调色

把 Balatro 涂成咖啡色只会得到一个"脏了的小丑牌"。1999 的视觉是一套**有配比的系统**
（80% 低饱和、60/30/10、8:2 疏密、低长调），照搬任何单点都会失衡。

真正可迁移的是结构，不是颜色。所以这次只动四层：

```
底色/影调  →  材质  →  装饰母题  →  字体
（其余维度锁死：功能色语义、信息层级、圆弦版式）
```

### 19.2 功能色不能跟着降饱和

这是整轮最重要的一条判断。

1999 的规矩是"80% 以上面积低饱和，高饱和只占 10–20%"。但 Balatro 的
蓝=筹码、红=倍率、金=金钱是**信息编码**，不是装饰。把它们一起灰掉，
玩家读数值要多花 200ms —— 在一手牌两秒的节奏里，这就是"手感变木"。

处理方式：色相保留，饱和度各降一档，明度整体向暖偏。

| 语义 | 原来 | 现在 |
|---|---|---|
| 筹码 | `#009DFF` 纯蓝 | `#5E9BB0` 灰蓝 |
| 倍率 | `#FE5F55` 亮红 | `#C9604F` 砖红 |
| 金钱 | `#F3B958` 金黄 | `#DCA85E` 琥珀 |
| 正向 | `#4BC292` 翠绿 | `#7FA184` 灰绿 |

深咖底上这三色的对比度分别是 4.3 / 3.9 / 6.2，都在可读区间。

### 19.3 罗马数字：一处白捡的母题

1999 用罗马数字做钟表刻度与档案编号；Balatro 的底注恰好是 1–8 的序数。
于是 `A3/8` 变成 `AIII/8` —— 不加任何新元素，两个系统自己咬合了。

用 ASCII 而不是 Unicode 罗马数字字符：后者在部分设备缺字形会出豆腐块，
而等宽字体下 `VIII` 的宽度是确定的。

### 19.4 牌背：占比最大的那块画布

一张牌背只有 22×30dp，但它在牌桌上是**成批出现**的，视觉总面积超过任何单张牌。
原来用的是 Bicycle 暖红斜网 —— 那是"扑克牌"的语义，不是"档案"的语义。

现在：深咖底 + 烫金双线框 + 四角星 + 雨滴斜纹。四角星压在正中偏上，
因为下半截会被手牌槽位裁掉。

### 19.5 三个尺寸上的取舍

- **网点（halftone）在小牌上不成立**。25dp 高的牌面画网点，点径不到 0.5dp，
  会糊成一层灰。改用"四角老化"（径向暗角）表达纸张，中心保持干净。
- **衬线只给大号字**。标题与筹码数字用 `FontFamily.Serif`，小字仍是 sans/mono。
  小屏上衬线细笔画会糊，可读性优先于气质。
- **雨滴只在边缘**。`FeltBackground` 的 30 条斜线全部落在画布外围，
  符合 8:2 —— 它们的作用是"暗示"，不是"纹理"。
